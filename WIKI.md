## 1. ИДЕЯ И ЦЕЛЬ ПРОЕКТА

Telegram-бот для генерации профессиональных product-фотографий женского белья (трусы) и централизованной навигации по каталогу артикулов для бренда **INTIMNO**.

**Задача бота:** помочь создавать красивые изображения трусов без фотографа — через нейросеть. Пользователь присылает фото своих трусов, бот генерирует готовое изображение в нужном стиле.

**Вторая задача (добавлена в августе 2026):** дать менеджерам быстрый доступ ко всем ссылкам по каждому артикулу (WB, Ozon, исходники, предметка, видео) прямо из Telegram, без открытия Google Таблицы.

**Ключевое условие для генерации:** без фото трусов генерация не запускается. Трусы — основа каждого кадра.

**Исходный документ:** файл `Прототип — Telegram-бот NanoBanana.md` — первоначальная концепция, которая в процессе работы значительно расширилась.

## 3. КАК СТРОИЛСЯ БОТ: ЭТАПЫ

### Этап 1 — Первая версия (2 функции)

Первая версия бота включала только то, что было в прототипе:
- **Функция 1 `/reference`** — пользователь присылает референс → Claude анализирует → составляет промпт → пользователь присылает фото трусов → генерация → 1 изображение
- **Функция 2 `/style`** — пользователь присылает фото трусов → выбирает стиль (Нежный / Тёмный) → 5 изображений

### Этап 2 — Исправление API-параметров

После получения реальной документации Replicate были исправлены параметры вызовов:

**NanaBanana Pro (до → после):**
```
было:   "width": 768, "height": 1024, "image": BytesIO(...)
стало:  "aspect_ratio": "3:4", "resolution": "1K",
        "output_format": "png", "safety_filter_level": "block_only_high",
        "image_input": [BytesIO(...)]   ← массив, не одиночное поле
```

**Claude Sonnet (до → после):**
```
было:   "prompt": system_prompt + user_prompt (всё в одно поле)
стало:  "system_prompt": ...,   ← отдельное поле
        "prompt": ...,
        "max_tokens": 4096,
        "extended_thinking": False
```

### Этап 3 — UX-улучшения (по запросу)

**Меню команд в Telegram:**  
При старте бот регистрирует команды через `bot.set_my_commands()` — они появляются в кнопке меню (иконка `/`) у пользователя.

**Приём изображений файлом:**  
Раньше бот принимал только сжатые фото из галереи. Добавлена поддержка файлов (PNG, JPG, JPEG, WEBP) — через `F.document` с проверкой MIME-типа.

**Отправка результата файлом:**  
Раньше бот отправлял сгенерированные изображения как сжатые фото (`answer_photo`). Это портило качество. Теперь бот скачивает PNG с Replicate через aiohttp и отправляет как документ (`answer_document`) — полное качество без сжатия Telegram.

### Этап 4 — Расширение функционала

**Функция 1 — 2 варианта вместо 1:**  
Claude теперь составляет 2 разных промпта по одному референсу. Запускаются 2 генерации параллельно → пользователь получает 2 варианта и выбирает лучший.

**Новая Функция 3 `/describe`:**  
Пользователь описывает желаемый стиль текстом (на русском или английском) → Claude составляет промпт → генерируется 1 изображение. Для тех, у кого нет референсов.

**Меню дополнительных элементов:**  
После получения фото трусов в любой функции бот предлагает добавить реквизит в кадр:

```
[📇 Визитка]         [📖 Журнал INTIMNO]
[✏️ Описать словами] [🖼 Прислать фото]
[✅ Без добавок — генерировать]
```

- **Визитка** → добавляет в промпт описание визитки с брендом INTIMNO
- **Журнал INTIMNO** → добавляет журнал в промпт
- **Описать словами** → пользователь пишет что добавить, текст вставляется в промпт
- **Прислать фото** → Claude анализирует фото реквизита и описывает его для промпта
- **Без добавок** → генерация запускается сразу

### Этап 7 — Динамическая генерация промптов для стилей

**Проблема:** в `/style` промпты были фиксированными — тексты, прописанные вручную. Каждый раз при одном и том же стиле генерировались похожие кадры.

**Решение:** промпты теперь генерирует Claude на лету перед каждой съёмкой.

**Как это работает:**

1. Вместо фиксированных промптов — шаблоны-описания стиля (`STYLE_BLUEPRINTS`). Каждый описывает характеристики стиля: поверхности, реквизит, освещение, настроение, углы съёмки.
2. В `services.py` добавлена функция `generate_style_prompts(style_description)` — отправляет шаблон в Claude и получает 2 уникальных промпта.
3. В `bot.py` в момент выбора стиля бот показывает `⏳ Подбираю идеи для съёмки...`, вызывает Claude, затем продолжает обычный флоу с меню реквизита.

**Результат:** каждая генерация уникальна — разные поверхности, реквизит, углы — но всегда в рамках выбранного стиля.

### Этап 11 — Строгая верность гарнмента (июль 2026)

**Проблемы по результатам тестирования:**
- Бот менял трусы в генерации — менял фасон/силуэт, добавлял кружево туда где его нет
- Бот описывал цвет и принт трусов в промпте вместо того чтобы дать модели рассмотреть фото
- При нескольких трусах — размещал их по углам кадра вместо компактной группы

**Решение:** переработан блок `_hard_rules_block()` в `services.py`.

| Правило | Суть |
|---------|------|
| SHAPE / CUT / SILHOUETTE | Фасон MUST оставаться как на фото |
| FABRIC / MATERIAL | Материал MUST оставаться идентичным |
| DO NOT ADD WHAT IS NOT THERE | Если на фото нет кружева — никогда не пишем «lace» |
| Цвет/принт не описываем | В промпте только количество + материал. Цвет и принты не описываем — модель видит фото |
| COMPOSITION LAYOUT | Несколько трусов — компактной группой, не по углам |

### Этап 12 — Навигация по каталогу и новое главное меню (август 2026)

**Запрос:** менеджерам нужен быстрый доступ ко всем ссылкам по каждому артикулу прямо из бота. Данные хранятся в Google Таблице.

**Реализация:** ветка `feature/catalog-navigation` (поверх `feedback-v2`).

#### Новый файл catalog.py

- Скачивает Google Sheets в формате **XLSX** (а не CSV!) — только XLSX сохраняет гиперссылки из ячеек-чипов
- Использует `openpyxl` для чтения ячеек и их гиперссылок (`cell.hyperlink.target`)
- Фильтрует только две нужные категории: **НИЖНЕЕ БЕЛЬЕ** и **БЫСТРЫЕ ЗАПУСКИ**
- Кэширует данные на диск (`catalog_cache.json`), автоматически обновляет раз в неделю
- Нечёткий поиск через `rapidfuzz` — без AI-токенов

#### Новые команды

| Команда | Что делает |
|---------|-----------|
| `/catalog` | Показывает inline-кнопки категорий → список артикулов с пагинацией → карточка со ссылками |
| `/find` | Запрашивает строку поиска → нечёткий поиск по всем артикулам → список результатов |

По каждому артикулу — кнопки: **WB · Ozon · Исходники (Яндекс Диск) · Предметка (Google Drive) · На моделях · Видео**  
Карточка показывает только название артикула + комментарий из таблицы (если есть).

#### Новое главное меню (/start)

`/start` теперь показывает inline-клавиатуру с двумя разделами вместо текстового списка команд:

```
[🎨 Генерация контента]
[🗂 Навигация по артикулам]
```

Каждый раздел открывает подменю со своими кнопками и кнопкой «← Назад».

#### Обновлённая справка (/help)

`/help` разделена на два блока: **Генерация контента** и **Навигация по артикулам** — с описанием каждой команды и форматов.

## 4. ЧТО БЫЛО ИСПРАВЛЕНО ПО ХОДУ

**1. Неправильные параметры API NanaBanana Pro**  
Изначально использовались `width`/`height` и поле `image`. После получения реальной документации API исправлено.

**2. Токены попали в `.env.example`**  
GitHub заблокировал пуш через встроенную защиту (Secret Scanning). Файл исправлен, коммит переделан.

**3. CSV → XLSX для каталога**  
CSV-экспорт Google Sheets не сохраняет гиперссылки из ячеек-чипов. Переключились на XLSX + openpyxl.

**4. Ветка создана от main вместо feedback-v2**  
Первоначально `feature/catalog-navigation` была создана от устаревшего `main`. Обнаружено через конфликты при попытке слить. Ветка пересоздана от правильного основания.
